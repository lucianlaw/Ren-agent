# Ren Agent

老板交代一件事，员工去做——每一步调用了什么工具、参数是什么、返回了什么、花了多久，全摊开给你看。

不是聊天窗口，是执行轨迹。员工是「岗位 + 人设 + 一个可随时替换的模型」，任务跑完要过交付物校验，模型说「做完了」不算数，文件真的在才算。

## 它是怎么分工的

```
浏览器  ── 登录 / 员工 / 任务 / 设置 / 云端存档  ──▶  云服务（Auth · Database · Storage）
   │
   ├──── 模型调用（流式 + 工具调用）  ──▶  云端 LLM 通道（免 Key）
   │
   └──── 每一步工具执行  ──▶  Node 工具执行器（隔离工作区里读写文件、搜内容、跑命令）
                                 └─ 执行完立刻后置校验，没过就把原因回灌给模型
```

- **业务数据不落本地盘**：员工、任务、配置、运行轨迹都在云数据库里，按登录账号隔离（RLS）。
- **不需要任何模型 Key**：模型走云端通道，用户在界面上选一个模型就行。
- **产出存云端**：任务写出来的文件自动归档到云存储，换设备能拿回来。
- **工具执行留在容器里**：读写文件、跑命令必须在有文件系统的一侧发生，所以由 Node 服务端做。

## 本地跑起来

需要 **Node.js 18+**，零依赖。

```bash
node server.js            # 默认 http://127.0.0.1:4319
```

本机只能看界面：云服务的数据面会校验请求来源，只接受**已发布域名**。登录、存数据、调模型都要在线上域名里验证——这是平台边界，不是 bug。

## 线上部署

```bash
PORT=8080 node server.js
```

需要满足两条：

1. 站点域名必须是云服务环境登记的发布域名（否则登录与数据面请求会被 Origin 校验拒绝）。
2. 前端 `public/cloud-config.js` 里的 `endpoint` / `publishableKey` / `oauthRelayBaseUrl` 必须来自该应用的 `publicConfig`，不要手改。

## 发布与回滚

发布不是一个动作，是四道门后面接一次上传。门在 `scripts/release.mjs` 里：

```bash
node scripts/release.mjs --check    # 只跑门，不写文件
node scripts/release.mjs            # 跑完四道门，写 build.json
```

1. **工作区必须干净**——否则线上跑的东西对应不到一个 commit，「回滚到上一版」没有落点。
2. **部署目录不许有密钥文件**——上传是把整个目录压包，密钥会一起到线上。
3. **全量测试必须通过**——闸门替人记，不靠人记。
4. **产物冒烟**——把将要上传的那一份单独跑起来（独立端口、独立密钥与数据目录），
   确认它能启动、`/api/health` 应答、版本标记对得上。起不来就不发。

四道都过之后才写 `build.json`（commit / 分支 / 时间 / 版本号），这个文件随发布上传，
`/api/health` 里的 `build` 字段就是它。**线上 `build` 显示「未标记」= 有人直接传了文件夹。**

### 为什么没有 staging 环境

试过了，做不到：这个平台**发布的目标是「应用」，不是目录**。我把同一份代码放进相邻目录
发布，返回的 `sandboxId` 和分享链接跟生产完全一样 —— 等于直接覆盖了生产（2026-11-05 实测）。
工具文档也写明「发布永远是覆盖，没有创建第二个应用的入口」。

所以「先在测试环境验、再上线」在这套平台上只能拆成两段：**发布前跑产物冒烟**（第 4 道门），
**发布后核对 `build.commit`**。真要独立的两套环境，得先有第二个应用（另一台主机或另一个工作区）。

```bash
node scripts/stage.mjs          # 只跑产物冒烟
node scripts/stage.mjs --keep   # 留着产物，自己点两下
```

回滚：

```bash
node scripts/release.mjs --rollback v0.4.0   # 切到某版（工作区必须干净）
node scripts/release.mjs --check             # 确认这版是好的
# 然后走一次正常发布
```

刻意不自动重新部署：回滚本身是有风险的动作，应该由人确认。

## 密钥放在哪

**不在部署目录里。** 部署是「把整个目录压缩上传」，放进去的密钥会同时存在于本机磁盘、
上传的压缩包、线上容器三处；本地和线上共用一把，还意味着本机脚本能伪造线上的文件签名。

统一由 `lib/config.js` 解析，位置是部署目录**同级**的 `.ren-secrets/`（0700，文件 0600），
可用 `REN_SECRET_DIR` 覆盖（staging 就该覆盖成自己的目录）：

| 文件 | 用途 | 环境变量覆盖 |
|---|---|---|
| `authn.key` | 文件访问签名 fk 的 HMAC 密钥 | `REN_AUTH_SECRET` |
| `alerts.key` | 告警队列运维 key | `ALERTS_KEY` |
| `self.key` | 只读自审令牌（不配 = 功能关闭） | `SELF_TOKEN` |

优先级：环境变量 > 密钥目录里的文件 > 首次运行生成。
历史的三个位置（`workspace/.authn.key`、`data/alerts/.key`、根目录 `self-token.json`）
在第一次读到时会被**复制**进密钥目录，所以升级当天已有的图片链接、告警任务不会失效；
默认只复制不删除（避免测试进程误删真实凭证），要搬走原件用 `REN_ADOPT_LEGACY=move`。

`/api/health?key=<运维key>` 的 `secrets` 字段会说明每个密钥的来源
（`env:` / `file` / `migrated` / `generated`）——**如果线上一直显示 `generated`，
说明密钥目录每次发布都丢了，签名会集体失效**，这是唯一能看出这件事的地方。

## 数据模型

| 表 | 用途 | 隔离 |
|---|---|---|
| `ba_staff` | 员工档案：名字 / 岗位 / 人设 / 备注 | `owner_id = auth.uid()` |
| `ba_tasks` | 任务：目标 / 交付物 / 状态 / 轨迹 / token / 上下文 | 同上 |
| `ba_settings` | 每人一份：模型、三个权限开关、步数与 token 上限 | 同上 |
| `ba_meetings` | 会议：主题 / 参会人 / 拆题 / 要素拆解 / 同事发言 / 纪要 / 会后追问 | 同上 |
| `ba_todos` | 待办：内容 / 负责人 / 期限 / 来源（会议或任务，可多个）/ 状态 | 同上 |
| `ba_kb` | 员工专属知识库：标题 / 原文 / 分块 / 字数 | 同上，按 `staff_id` 再隔离 |

六张表都开了 RLS，客户端从不发送 `owner_id`，由数据库 `DEFAULT auth.uid()` 填。

员工都带 `core`（核心）标记，核心员工在召集会议时默认被勾选。本期所有员工都是 AI（`kind` 一律 `ai`），真人成员的入口已移除。

## 员工档案与知识库

- **岗位**：下拉 + 汉字搜索（输入「设」就能筛出产品设计 / 工业设计 / 视觉设计 / 交互设计），也允许直接输入列表里没有的岗位。
- **名字**：选填。不填就用岗位名顶上（例如只选「财务」，员工就叫「财务」）。
- **期望员工具备的能力**：写进员工档案，任务和会议发言时都会作为它的能力边界提示。
- **知识库（RAG）**：每位员工一份，只按 `staff_id` 取，谁都看不到别人的。
  - 导入：粘贴文本，或选 `.txt / .md / .csv / .json` 文件（≤2MB）。按原文空行分段切块，超长段按句末切。
  - 查看：列出每份资料的标题、字数、段数、导入时间，可展开看前 800 字，可删除。
  - 检索：不联网、不外传。用中文二元组命中率给段落打分，任务执行前取最相关的 3 段、会议发言前取 2 段，拼进这位员工的 system prompt。
  - 新员工还没保存就导入的资料会先挂在临时区，员工保存上岗时自动归到它名下（已登录则同时写入云端）。


## 待办

顶栏「待办」是会议与任务产出的待办总台账，按产生时间倒序。

- **入池时机**：会议出纪要时、会后每一轮收口时，秘书给的待办自动进来；任务卡在权限上时，会自动生成一条「等你授权」的待办。
- **来源标签**：每条待办挂着来源标签——`会议 · 主题` / `任务 · 标题`，点标签直接跳过去。来源被删掉时标签置灰标「已删除」。
- **多会议关联**：一条待办可以关联多场会议（比如同一件事在两场会上都提过）。点「＋ 关联会议」勾选即可，标签会并排显示。
- **派成任务**：会议纪要里的「把待办变成任务」会把对应待办派成任务，并在待办上补一个 `任务 · 标题` 标签，形成「哪场会 → 哪条待办 → 哪个任务」的可追溯链。


## 工具与权限

| 开关 | 开了之后它能做什么 |
|---|---|
| 读文件 | 列目录、读文件、搜内容 |
| 写文件 | 新建/覆盖工作区里的文件（默认开） |
| 跑命令 | 执行 shell（黑名单拦 `rm -rf`、`sudo`、`git push --force` 等，默认关） |

权限在两侧各判一次：前端没开就不发，前端被绕过服务端也拒。

## 会议：先问清楚，再分头拆

老板只给一个主题，剩下的四步走：

1. **秘书拆题** —— 一句话说清「这次到底要拍什么」，再问最多 3 个问题；每个问题都得是老板一句话能答、且答案会改变后面的方向，并给 2–4 个具体选项。拿不准的先写成默认假设，不占老板时间。
2. **老板拍板 / 纠正** —— 点选项，或直接说；答完秘书收敛成一句确认口径，连同拆解方案一起摊给老板看。不满意就接着说，它按新口径重排。
3. **拆要素、派活** —— 方案、设计、技术可行性、成本、销售、运营、风控、财务、法务……只留真正相关的 3–8 块；每块指派一位参会同事、给一个具体问题、指定一种方法（5W2H / MECE / PDCA / SWOT / RACI / 风险矩阵 / 盈亏平衡 / 鱼骨图 / 六西格玛 / 6S 等）。
4. **同事并行发言 + 秘书收口** —— 同一个人负责的几块合并成一次发言，最多 3 个人同时说；最后出纪要：结论、已定事项、待办（做什么 / 谁 / 什么时候）、风险、只有老板能拍的。

纪要里的待办可以一键变成任务，直接进任务池。

## 「完成」不由模型宣告

- **单步校验**：写文件查是否真的落盘、内容是否明显缩水；跑命令查退出码。
- **交付物校验**：任务声明了 `报价结论.md`，跑完就必须真有这个文件且非空，否则状态是 `unverified`。
- **上限闸**：单任务步数上限、token 上限，超了就停，不继续烧。

### 验收结论去哪了

验收（谁验的、各维几分、缺口是什么）属于内部质检，**不进老板的任务界面**：
对话里不再有验收卡，产出清单里也不会出现 `*_验收.md` / `*_验收.json` 这类自检中间产物，
`weak` 状态在界面上按「已完成」显示。

没过验收 / 执行报错 / 预算超限，改投一条告警进服务端队列（`lib/alerts.js`）：

| 接口 | 用途 |
|---|---|
| `POST /api/notify` | 前端投递告警（同源） |
| `GET /api/alerts?key=…&days=3` | 消费方拉未发告警（`all=1` 看全部） |
| `POST /api/alerts/ack` | 发完信打卡，避免重复发 |

队列落盘在 `data/alerts/YYYY-MM-DD.jsonl`，打卡记录在 `data/alerts/mailed.json`。
收件人默认 `livincuzlove@agent.qq.com`，可用 `ADMIN_EMAIL` 覆盖。

读队列的 key：优先取 `ALERTS_KEY` 环境变量，否则用密钥目录里那份随机串
（首次运行自动生成，权限 600，位置见下一节）。**不再有写死在源码里的默认 key**——多人场景下那等于
把「所有人的任务标题」对每个登录用户开放。登录用户不带 key 时只能看到自己工作区的告警，
带对 key 的运维消费方才能拿全量。

发信不在服务端做（容器里没有邮件凭据），由每个工作日 09:00 的定时任务拉队列汇总后发给管理员。
线上域名过网关时**每个请求都要带 `?sharecode=`**，POST 还要带 `Origin` 头，否则会被同源校验挡下。

**额度用完的续跑**：任务累计 token 超过上限后，点「继续跑」原来会在 agent 循环第一行被
`累计 > 上限` 直接踢出来（界面像没反应）。现在续跑前会把额度补到「已花 + 再跑一轮的余量」，
按钮也按状态改口径——额度过顶的任务显示「加额度接着跑」。

## 工作区隔离（多人在线）

一个账号一个目录：`workspace/users/<sha256(账号uid) 前 32 位>`。目录名不是凭证，
只是地址——**谁是谁由服务端问云端决定**（`GET /.cloud/auth/v1/user/me`，拿 sub），
客户端传来的 uid / scope 一律只看不用。同一账号换设备、换浏览器落在同一个目录。

每个请求入口都把「验过的身份」放进 `AsyncLocalStorage`，`scopeKey()` 从上下文取，
所以并发请求之间不会串号（模块级变量会）。

隔离面是这几条，都有测试钉住（`test/multiuser-test.mjs`，用两张真凭证互相试探）：

| 面 | 边界 |
|---|---|
| 文件 / 上传 / 预览 / 下载 | 路径围栏在自己目录内；`?scope=` 传别人的值被无视 |
| `<img>`/下载链接 | 必须带服务端算的 `fk`（HMAC），只能开自己那扇门 |
| 完全访问模式 | 读写执行全开也只放开「工作区之外」，`workspace/` 下别人的目录仍然拒绝 |
| 跑命令 | `../`、工作区根的绝对路径、`${PWD%…}` 裁剪一律拒；**但这不是硬沙箱** |
| 记忆 / 权限 / 审计 / 告警 | 各自按 scope 落盘，读接口只读自己那份 |
| 任务事件流 / 停止 / 插话 / 审批 | 必须是任务主人，知道 runId 也只能看自己的 |

已知边界（别对外说成「已经隔离」）：

- 状态（进行中的任务、锁、限流桶）在进程内存里，重启即失，且只支持单进程。
- 磁盘配额是**应用层软配额**：写工具（`write_file` / `edit_file` / `make_*` / 上传）在写之前拦，
  但 `run_shell` 里的降权子进程想写什么拦不住——那是 OS 边界，不是代码边界。
  所以 shell 走「跑完实测 + 超限冻结」，冻结后所有写入口一律拒绝，直到清理或提额。
- `run_shell` 是黑名单 + 路径形态检查，不是容器。能挡住顺手越界，挡不住蓄意逃逸
  （真正挡住越界的是 `lib/sandbox.js` 的 uid-split，见下）。
- 单进程 Node 是单线程：十个人同时跑重任务会互相等 CPU。

## 备份与恢复

三处状态会丢、且丢了回不来：`data/`（审计 / 告警 / 权限 / 额度）、`workspace/`（每个人的文件）、
`SECRET_DIR`（签名密钥）。备份是给这三处拍的快照。

```bash
node scripts/backup.mjs              # 立刻备份一次
node scripts/backup.mjs --status     # 上次成功是几小时前
node scripts/backup.mjs --keys       # 连密钥一起（末日恢复用，需人工在机器上敲）

node scripts/restore.mjs --list                    # 有哪些份
node scripts/restore.mjs --verify ren-....tar.gz   # 校验完整性
node scripts/restore.mjs --file ren-....tar.gz --dry-run
node scripts/restore.mjs --file ren-....tar.gz --yes   # 真的恢复
```

- **位置**：默认 `../.ren-backups`（部署目录之外，0700）。放在目录里会被下一次部署覆盖，
  而「要回滚数据」恰恰发生在那之后。
- **格式**：自己写的 tar.gz（不调系统 tar——中文长路径过 shell 引号、macOS 与 GNU 行为不一致），
  包内第一项是 `manifest.json`，逐文件 sha256。
- **定时**：进程启动后每 10 分钟检查一次「距上次成功是否超过 `REN_BACKUP_HOURS`」（默认 24）。
  判断依据是落盘的 index，所以重启不会把计时重置。
- **轮转**：默认留 7 份（`REN_BACKUP_KEEP`）。空包当失败——一份 0 文件的备份会把好的旧备份挤掉。
- **密钥默认不进包**。需要时单独出一份 `.keys.tar.gz`，恢复必须显式 `--with-keys`。
  HTTP 侧**没有**这个能力：一个带 key 的请求不该能把签名密钥导出成文件。
- **恢复顺序**：校验 sha256 → 先给当前状态拍一份 `pre-restore` → 解到临时目录 → 才覆盖。
  任何一步失败就停。默认是「合并覆盖」，不是「清空重来」。

运维接口（需要运维 key，`?key=<alerts.key>` 或管理员账号）：
`GET/POST /api/admin/backup`、`POST /api/admin/backup/verify`。

## 额度（token / 磁盘）

在此之前这两件事都没有上限：token 只有单任务预算闸，磁盘只有单文件 24MB。

| 项 | 默认 | 环境变量 | 行为 |
|---|---|---|---|
| token / 天 | 500,000 | `REN_TOKEN_DAILY` | 发起前 402；跑的过程中撞线即中止任务 |
| token / 月 | 5,000,000 | `REN_TOKEN_MONTHLY` | 同上 |
| 磁盘 / 账号 | 512MB | `REN_DISK_MB` | 写前拒绝（上传 507 / 冻结 423） |

- **计量来源**：上游 `usage` 帧优先；拿不到就按字符估（中文约 1 字 1 token），
  两种分开记——`/api/quota` 会给出 `estimated` 占比，看着的数是不是账单一眼能分辨。
- **落盘**：`data/usage/<scope>.json`。内存累加 + 5 秒 flush + 退出时 flush，
  所以重启不会把用量清零（否则「重启即重置」就是最好用的绕限方法）。
- **用户自助**：`GET /api/quota` 看用量，`POST /api/quota/thaw` 在清理后自己解冻
  （服务端实测，要降到上限 80% 以下才放行——贴着上限解冻会立刻再撞一次）。
- **运维**：`GET/POST /api/admin/quota` 列出所有账号、按账号覆盖额度、解冻。

## 记忆

两层：公司档案（`memory/<scope>/company.md`）和员工个人记忆（`memory/<scope>/staff/<id>.md`）。
正文是给人看的 md，元数据（类型 / 重要度 / 用到次数 / 状态 / 取代关系 / 来源任务）另存 `<kind>.meta.json`。

- **状态**：`有效` → `已被取代`（新说法推翻旧说法，旧行留档但不再召回）／ `已停用`（老板手动关掉）
- **冲突**：新事实与旧事实说的是同一件事且数字/否定变了，旧条自动标「已被取代」；
  模型在【记忆】里写 `- 更正：新说法` 时无条件取代最像的那条
- **敏感**：密钥 / 密码 / 证件号 / 银行卡 / 私钥一律不写进记忆（公司档案整篇粘贴时改为打码）
- **召回**：只取有效条目，打分 = 关键词命中 ×2 + 重要度 + 被用过次数 + 时间新鲜度
- **可控**：记忆面板可按类型筛、单条停用/纠正/标重要/删除，点来源能跳回产生它的那次任务

## 它现在还不能做什么

- **多端会冲突**：同一账号在两个浏览器同时跑，工作区各是各的（scope 不同），云端任务会互相覆盖。
- **沙箱是「进程降权」而不是「容器」**：`lib/sandbox.js` 在 Linux + root 下给每个账号分配独立 uid、
  目录 700 并降权执行（实测挡住了「用一行 JS 读别人文件」那条路），但没有 CPU / 内存 / 进程数配额；
  一台机器仍然可能被一个账号算力吃满。没有隔离能力时 `run_shell` 直接拒绝，不会假装安全地照跑。
- **还没有项目级共享记忆**：项目结论散在各任务的产出里，换个员工接手同一项目还得重新讲一遍。
- **Windows 没测过**：`run_shell` 走 `/bin/sh`。
